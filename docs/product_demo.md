# CoursePilot 产品展示与投递准备

新版独立 Web 前端与 FastAPI 同源运行，访问 `http://127.0.0.1:8000/web/`（若后端使用其他端口，替换端口即可）；`localhost:8501` 是迁移期保留的旧 Streamlit 页面。前端采用正式学习平台布局，登录页只保留账号登录和注册入口。教师侧栏为“待办事项 / 课程资料 / 题库与考试 / 主观题批改”，学生侧栏为“课程中心 / AI 学习助手 / 课程考试 / 考试成绩”；桌面端侧边栏固定显示。资料上传后进入知识点片段审核；题目 CSV 选择后先预览并按行、字段校验后导入。

管理员创建的课程先处于草稿状态，确认发布后才对学生开放并进入教师授权选项。管理员可查看和撤销已有教师课程授权。教师待办聚合自己课程中的资料解析或索引失败、待审核片段标签及待批改主观题，并跳转到对应页面。学生在结构化计划中可点开当前会话、当前课程允许访问的错题和资料原文；填写全部自测回答后，任务完成状态持久化到该会话的具体计划消息。任务完成是学生自报进度，不等同于自动判定掌握知识。

## 建议展示的 3 分钟主线

1. **教师端（约 50 秒）**：登录有课程授权的教师账号，展示按课程筛选的题库、CSV 批量导入、选择多道题建草稿、重新打开草稿并发布；再只填写文件和标题上传一份含多个知识点的讲义，展示系统建议标签、教师查看原文后修改或新增标签，以及双索引状态。使用事先准备好的测试课程，避免录屏时等待 embedding 建索引。
2. **学生端（约 50 秒）**：登录已选课学生，参加已发布的考试并提交。展示客观题自动判分；如试卷含简答，切回教师端批改，回到学生端查看最终成绩和错题。
3. **Agent（约 60 秒）**：在这门课程的新会话中提问“根据我的错题制定复习计划”。展示错题分析、课程资料检索、结构化计划与引用来源；再问“刚才那道题为什么错”或“第二段资料是什么”，展示跨轮追问与原文重取。另用零错题账号问“我有哪些薄弱点”，确认不会编造。
4. **工程说明（约 20 秒）**：展示 API 文档、`tool_trace` 和评测报告。说明单 Agent / Multi-Agent 均已实现；v3 是 60 条固定回归用例，真实 RAG 相关性与 Gold 教学质量尚需单独验证。

录屏前检查：API `/health` 返回 `ok`；前端可登录；教师有课程授权；学生已选课；资料索引显示可用；DeepSeek、MCP 和向量服务可访问。演示失败时保存原始状态与工具轨迹，避免把服务故障解释成“学生资料不足”。

## 对外展示材料

- GitHub 首页：根目录 `README.md`，包含项目定位、架构、启动步骤和评测边界。
- 录屏：建议 2～4 分钟，使用虚构账号及测试数据；遮挡浏览器令牌、环境变量和个人信息。
- 截图：教师题库与资料状态、学生考试结果、含来源的复习计划、评测汇总各一张。
- 简历项目链接：仓库公开后使用真实的 `https://github.com/<用户名>/<仓库名>`；录屏可作为 README 的补充链接。现在项目目录尚未初始化 Git，也没有远程仓库，不能填写一个占位链接冒充已发布地址。

## 发布前核对

`.gitignore` 已排除 `.env`、本地 `data/`、Chroma 运行目录、缓存和逐例评测输出。公开前仍需逐文件检查历史资料和录屏是否含口令、API Key、令牌或真实学生信息。将 `.env.example` 作为配置说明；不要把 `.env` 或本机数据库推送到 GitHub。

推荐在首次提交前用 `git status --short` 和 `git ls-files` 检查待提交文件；若已有历史提交，需同时检查历史提交中是否存在密钥。对外发布属于外部操作，应在内容与隐私核对完成后执行。
